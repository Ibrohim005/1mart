# Как вносить изменения

## Ветки

| Ветка | Зачем |
|---|---|
| `main` | то, что готово к выкладке. Пишем только через merge request |
| `dev` | рабочая ветка, сюда вливаются задачи |
| `feat/…`, `fix/…` | одна задача — одна ветка от `dev` |

## Перед коммитом

```bash
npm run lint
npm run typecheck
npm run test:e2e
```

Те же три проверки гоняет CI на каждый merge request. Красный конвейер
не вливаем — это дороже, чем починить сразу.

## Сообщения коммитов

Одна строка, по-русски, в настоящем времени, без точки в конце. Что сделано,
а не что изменилось в файлах:

```
корзина: удаление одним путём с отменой
seo: заголовки и описания на узбекской локали
```

## Вёрстка

Размеры, цвета и шрифты берутся из макета Figma, а не на глаз. Если
отступаем от макета — строка в таблицу «Отступления от макета» в
[UI-KIT.md](UI-KIT.md) с объяснением почему. Иконки только выгрузкой из
Figma, рисовать руками нельзя.

## Тексты

Русских строк в разметке быть не должно: всё через `$t()`, ключи лежат в
`apps/host/i18n/locales`. Проверить, сколько ждёт перевода:

```bash
npm run i18n:todo
```

## Секреты

`.env.local` и любые токены в репозиторий не попадают. Если токен всё же
утёк в коммит — отзываем его в сервисе, а не просто удаляем строку:
история остаётся.
