# Paylov Market — фронтенд

Маркетплейс платёжного приложения Paylov (АО «Octagram»): электроника, одежда,
товары для дома и другие категории с доставкой по Узбекистану. Основа — витрина
Zoo Market (дизайн и компоненты), структура главной — по образцу Uzum Market,
логика оплаты — по ТЗ Paylov (кошелёк или карта, резерв до подтверждения
продавцом, подтверждение кодом, доставка Express 24 / Maxsus / Яндекс).

Запуск: `npm install`, затем `npx nuxt dev apps/host --port 3300` → http://localhost:3300
Здесь лежит **только фронтенд**: вёрстка по макету Figma и слой моков,
который отдаёт те же данные и в том же формате, что потом отдаст бэкенд.

**Правила работы с проектом: [RULES.md](RULES.md).**

## Что внутри

| | |
|---|---|
| Стек | Nuxt 4, Vue 3, TypeScript, Pinia |
| Структура | npm-workspaces + слои Nuxt (`layers/*`), приложение — `apps/host` |
| Языки | русский и узбекский (`/` и `/uz`), маршруты через `@nuxtjs/i18n` |
| Данные | слой `layers/api-mock` — эндпоинты внутри Nuxt, формат `{ payload, errors }` |
| Тесты | Playwright, 211 сценариев в трёх движках |
| SEO | sitemap, robots, schema.org, hreflang, canonical, og-теги |

### Слои

```
apps/host          приложение: конфиг, локали, публичные файлы
layers/shared      UI-кит, токены, утилиты, общие композаблы
layers/app-shell   шапка, подвал, макеты, диалоги
layers/catalog     главная, категории, поиск, страница продавца, /info/*
layers/pdp         карточка товара
layers/cart        корзина
layers/checkout    оформление заказа
layers/account     личный кабинет
layers/api-mock    моки API — удаляется, когда появится бэкенд
```

## Запуск

Нужен Node 20 или новее и npm 10.

```bash
npm install
cp .env.example .env.local
npm run dev
```

Откроется `http://localhost:3000`. Переменные окружения — в `.env.example`,
свои значения кладите в `.env.local` (он в `.gitignore`).

## Подключение бэкенда

Слой `layers/api-mock` поднимает внутри Nuxt те же адреса, которые потом
отдаст сервер. Порядок подключения:

1. Выставить `NUXT_PUBLIC_API_BASE` на адрес API.
2. Убрать `layers/api-mock` из `extends` в `apps/host/nuxt.config.ts`.

Код приложения при этом не меняется. Полный список эндпоинтов, форматы
ответов и места подключения — в [BACKEND.md](BACKEND.md). В коде моков
рядом с каждым эндпоинтом стоит пометка `TODO: Connect to backend endpoint`.

## Макеты

Исходники Figma в репозиторий не кладём: это 72 МБ PNG, которые не нужны для
сборки и навсегда раздувают историю. Доступ к файлу Figma — у владельца
проекта. Для выгрузки нужен личный токен, он кладётся в `.env.local`
(`FIGMA_TOKEN`), в репозиторий не попадает.

## Как вносить изменения

1. Ветка от `dev`: `feat/что-делаем` или `fix/что-чиним`.
2. Перед коммитом: `npm run lint`, `npm run typecheck`, `npm run test:e2e`.
3. Merge request в `dev`. В `main` попадает только то, что готово к выкладке.

Правила вёрстки — в [UI-KIT.md](UI-KIT.md). Главное: размеры берутся из
макета, а не на глаз; любое отступление записывается в таблицу отступлений
с объяснением почему.
