## Заголовки

Задаются в `apps/host/nuxt.config.ts` → `routeRules['/**'].headers`.
В режиме разработки часть заголовков подставляет сам Nuxt, в собранном
приложении — нет, поэтому они прописаны явно.

| Заголовок | Значение | Зачем |
|---|---|---|
| `Content-Security-Policy` | см. ниже | ограничивает источники скриптов, стилей, картинок и запросов |
| `X-Content-Type-Options` | `nosniff` | браузер не угадывает тип ответа |
| `X-Frame-Options` | `DENY` | запрет встраивания в iframe (кликджекинг) |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | на чужие домены не уходит полный путь |
| `Permissions-Policy` | `camera=(), microphone=(), geolocation=(self), payment=()` | камера, микрофон и платёжный API не нужны; геолокация разрешена только своему origin — её просит карта адреса |
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains` | только HTTPS |

Политика:

```
default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline';
img-src 'self' data: blob: https://tile.openstreetmap.org; media-src 'self'; font-src 'self' data:; connect-src 'self';
frame-ancestors 'none'; form-action 'self'; base-uri 'self'; object-src 'none'
```

### Почему `'unsafe-inline'`

Два места требуют инлайна, и оба — не пользовательские данные:

1. **Скрипты** — Nuxt встраивает payload гидратации инлайн-скриптом, а `@nuxt/image`
   вешает на картинки собственный обработчик `onerror="this.setAttribute('data-error', 1)"`.
2. **Стили** — Vue пишет scoped-стили и вычисляемые `style`-атрибуты инлайном.

Это ослабляет защиту от XSS, поэтому **когда появится бэкенд, инлайн нужно
заменить на nonce**: сервер генерирует `nonce` на каждый ответ, подставляет его
в `script-src 'nonce-…'` и в теги. Отдельной строкой в разделе «Для бэкенда».

### Маршруты `/api/**`

`routeRules` не покрывает серверные роуты Nitro, поэтому у них свой набор.
Для JSON это не проблема: стоит `Content-Type: application/json` и `nosniff` —
браузер не станет исполнять ответ как HTML. Проверено запросом с payload.

## `v-html` — единственное вхождение

`layers/shared/app/components/ui/Icon.vue` вставляет SVG через `v-html`.
Разметка берётся не из сети и не из пользовательского ввода, а из
`import.meta.glob('../../assets/icons/*.svg', { query: '?raw' })` — то есть
из файлов репозитория, вшитых в сборку. Подставить туда чужую разметку
нельзя: имя иконки используется только для поиска по этому списку, и если
совпадения нет, компонент отрисовывает пустоту.

**Правило:** `v-html` допустим только для содержимого из сборки.
Для чего угодно, приходящего с бэкенда, — обычная интерполяция.

## Cookie сеанса

`zoo_auth` (`layers/app-shell/app/stores/auth.ts`):

| Флаг | Значение | Почему |
|---|---|---|
| `sameSite` | `lax` | защита от CSRF при переходах с чужих сайтов |
| `secure` | `!import.meta.dev` | по HTTPS не уходит в открытом виде; в dev протокол `http` |
| `path` | `/` | одна cookie на всё приложение |
| `httpOnly` | **не стоит, намеренно** | фронт на моках сам читает сеанс |
| `maxAge` | 30 суток | |

**Это временная cookie.** Она держит только имя и телефон для отрисовки шапки.
Настоящий токен сеанса выставляет сервер, и он обязан быть `httpOnly` —
из JavaScript его читать нельзя.

внутри `fontless` (транзитивная зависимость `@nuxt/fonts`).
Advisory GHSA-g7r4-m6w7-qqqr: чтение произвольных файлов **при запущенном
dev-сервере esbuild на Windows**. Продакшен-сборки и не-Windows разработка
не затронуты. `npm audit fix` версию не поднимает — ждём обновления `fontless`.

Проверять перед каждым релизом:

```bash
npm audit --omit=dev
```

## Для бэкенда

Фронт это сделать не может — перечислено, чтобы не потерялось.

1. **Сессия** — `httpOnly` + `Secure` + `SameSite=Lax` cookie, выставляется сервером.
   Клиентская `zoo_auth` в проде должна остаться только витриной или исчезнуть.
2. **CSRF** — токен на изменяющие запросы (`POST`/`PUT`/`PATCH`/`DELETE`)
   либо строгая проверка `Origin`/`Referer`.
3. **CSP с nonce** — отдавать `nonce` в заголовке и подставлять в теги,
   убрать `'unsafe-inline'` из `script-src`.
4. **Ограничение частоты запросов** — на вход, отправку SMS-кода, поиск.
5. **Валидация на сервере** — клиентские проверки в формах нужны для удобства,
   доверять им нельзя.
6. **Заголовки на уровне прокси** — если перед приложением стоит nginx или CDN,
   заголовки из `routeRules` могут быть перезаписаны; проверить итоговый ответ.
7. **HTTPS и HSTS** — `Strict-Transport-Security` уже отдаётся приложением,
   но редирект с `http` на `https` делает прокси.
8. **Логи** — не писать в них телефон, токены и содержимое cookie.
