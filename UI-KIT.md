# Единая стилистика Zooelon

Один источник правды для размеров, цветов и поведения. Значения сняты из
Figma-файла «Zooelon» (экраны SIng / Card / Location / Procode и Market web site).
Нельзя задавать эти величины числом в компоненте — только через токен.

Токены живут в `layers/shared/app/assets/css/tokens.css`.

## Диалоги

| Токен | Значение | Где |
| --- | --- | --- |
| `--overlay-bg` | `rgb(82 82 82 / 60%)` | затемнение под любым окном |
| `--overlay-z` | `300` | слой затемнения |
| `--dialog-width` | `586px` | стандартная ширина окна |
| `--dialog-radius` | `30px` | скругление панели |
| `--dialog-padding` | `22px` | внутренние поля |
| `--dialog-title-size` / `--dialog-title-line` | `27.1px` / `32.8px` | заголовок, Inter 700 |
| `--dialog-title-color` | `#27383F` | цвет заголовка |

Базовое окно — `UiModal`. Оно само делает затемнение, закрытие по Esc,
по клику мимо панели и по крестику. Новое окно начинается с него:

```vue
<UiModal v-model="open" title="Заголовок">
  <p>Содержимое</p>
  <template #footer>
    <UiButton block @click="submit">Подтвердить</UiButton>
  </template>
</UiModal>
```

Окна со своей раскладкой (выбор категории, адрес доставки, просмотр фото)
не дублируют стили: они берут те же токены затемнения и скругления.

### Поведение окна — `useDialog`

Внешний вид может отличаться, поведение — нет. Всё, что ниже, живёт
в `layers/shared/app/composables/useDialog.ts`, и любое окно обязано его вызвать:

- прокрутка фона блокируется, ширина полосы компенсируется паддингом, чтобы страница не дёргалась;
- вложенные окна считаются — прокрутку возвращает только последнее закрывшееся;
- при открытии фокус уходит на первый фокусируемый элемент окна;
- `Tab` и `Shift+Tab` ходят по кругу внутри окна и не выпадают на фон;
- `Esc` закрывает;
- при закрытии фокус возвращается на элемент, который окно открыл.

`UiModal` вызывает его сам. Окну со своей раскладкой нужны `ref` на панель и три строки:

```vue
const panel = ref<HTMLElement | null>(null)
useDialog(toRef(props, 'modelValue'), { panel, onClose: close })
```

```vue
<div ref="panel" role="dialog" aria-modal="true" aria-label="…" tabindex="-1">
```

Свой слушатель `Escape` при этом не нужен — он будет дублировать общий.

### Внутренние поля окна

В макете они у каждого окна свои — 18, 20, 25, 31, — поэтому единого значения
нет. По умолчанию 20px, остальное задаётся окном:

```vue
<UiModal v-model="open" title="Нужен аккаунт" body-padding="30px 25px 25px">
```

| Окно | Значение из макета |
| --- | --- |
| Вход / регистрация | `30px 25px 25px` |
| Промокоды | `21px 25px 28px` |
| Добавить карту | `24px 18px 31px` |
| Остальные | `20px` (по умолчанию) |

## Крестик

Единственный вариант — `UiCloseButton`. Размер `--close-size` 34, фон
`--close-bg`, при наведении `--close-bg-hover`. Отдельные `.dialog__close`,
`.loc__close`, `.picker__close` удалены — новые заводить нельзя.

```vue
<UiCloseButton @click="close" />
```

## Кнопки

`UiButton` — три вида и два размера.

| Пропс | Значения | Когда |
| --- | --- | --- |
| `variant` | `primary` (зелёная), `secondary` (серая), `ghost` (текстовая) | основное / второстепенное / ссылка-действие |
| `size` | `md` (`--control-height` 56), `lg` (`--control-height-lg` 68.8) | внутри карточек / главная кнопка диалога |
| `block` | флаг | кнопка на всю ширину |

Скругления — `--control-radius` 16 и `--control-radius-lg` 21.9.
У всех видов есть `:hover`, `:active`, `:disabled` и `:focus-visible`
с общим кольцом `--focus-ring`.

## Поля ввода

`--field-height` 48, `--field-radius` 14, фон `--color-field`.
Поиск в шапке, поиск в диалоге категорий и поля адреса используют их.

а разнобой уходит. Было 78 разных кеглей на страницах, стало 31.

**Что в шкалу не входит:**

1. **Карточка товара.** Её размеры считаются от `--u`, потому что макет даёт
   три масштаба одной карточки (1 / 1.199 / 0.95). Значения вроде 20.86 или
   25.66 — это производные, а не разнобой.
2. **Баннер на главной** (34, 61.8, 63.7) и поля кода в диалогах входа
   (50.1, 56) — единичные экранные кегли, для них токен был бы именем
   на один вызов.

## Текстовые блоки: line-height обязателен

`line-height: normal` в карточках PDP давал строку 62px вместо макетных 54 —

| Заголовок строки | Inter 15.36/18.59 w600 |
| Описание строки | Inter 13.44/16.26 w400 |
| Метка характеристики | Inter 18.38/25.11 w500 |

## Карточка товара: два размера

Макет даёт одну карточку в двух размерах — 239×532 на полках главной
(`Home`) и 287×638 в сетке каталога (`Ca`). Это не два компонента, а один,
увеличенный ровно в **1.199 раза**: коэффициент одинаков для всех девяти
текстовых узлов, высоты фото, кнопки и всех отступов.

Поэтому все длины в `UiProductCard` заданы в единицах `--u`:

```css
.card { --u: 1px; }                  /* полки главной */
.grid :deep(.card) { --u: 1.199px; } /* сетка каталога и поиска */
.useful__list :deep(.card) { --u: 0.95px; }  /* лента «Может пригодиться» */
```

Новое место, где карточка крупнее или мельче, меняет только `--u` —
трогать отдельные значения не нужно и нельзя, иначе размеры разъедутся.

## Карта адреса

Настоящая карта на Leaflet с тайлами OpenStreetMap. Библиотека лежит в сборке,
внешних скриптов нет — CSP ослаблять не пришлось, в `img-src` добавлен только
домен тайлов.

- клик по карте и перетаскивание метки переставляют точку;
- кнопка со стрелкой определяет местоположение через `navigator.geolocation`,
  по нажатию, без автозапроса;
- координаты показываются под картой и уходят вместе с адресом.

Два места, о которые легко споткнуться:

1. **`Permissions-Policy` должен разрешать геолокацию своему origin.**
   В заголовках стоит `geolocation=(self)`; при `geolocation=()` браузер
   блокирует запрос, а компонент показывает «Доступ запрещён».
2. **Карту создаём после открытия окна** (`watch` на `modelValue` + `nextTick`):
   до этого её контейнера нет в DOM, и Leaflet считает размеры нулевыми.

Стандартную иконку Leaflet не используем — она ищет картинки по путям,
которых в сборке нет. Метка рисуется через `L.divIcon` и стилизуется
глобальным правилом: scoped-стили до неё не доходят.

В тестах тайлы подменяются прозрачным пикселем через `context.route` —
прогон не должен зависеть от сети.

## Боковые колонки: остаются на месте

Фильтры каталога, блок покупки, «Ваш заказ» и меню кабинета не уезжают
при прокрутке — рядом лежащий контент скроллится под ними. Делается одним
классом:

```vue
<div class="category__sidebar sticky-aside">
```

```css
.sticky-aside {
  position: sticky;
  top: var(--sticky-top);           /* высота шапки + 16px */
  max-height: calc(100vh - var(--sticky-top) - var(--sticky-gap));
  overflow-y: auto;
}
```

Два условия, без которых не работает:

1. **Родитель — `align-items: flex-start`.** Иначе колонка растягивается
   на всю высоту строки и прикрепляться ей не к чему.
2. **Соседняя колонка выше.** Закрепление живёт внутри своей строки: когда
   боковая колонка сама самая высокая (например, меню кабинета рядом с короткой
   страницей), запаса для закрепления нет и она уезжает вместе со строкой.
   Это не ошибка — смотреть рядом с ней уже нечего.

`max-height` с внутренней прокруткой обязателен для высоких колонок: сайдбар
фильтров 1253px, блок покупки 1572px — без него их низ недостижим,
пока колонка закреплена.

`scroll-behavior: smooth` здесь не ставим: прокрутка внутри фильтров должна
быть мгновенной.

**Осторожно с flex-колонками.** Если колонка — `display: flex`, её содержимое
при `max-height` начинает сжиматься вместо того, чтобы уйти в прокрутку:
переключатель «Животные / Зоотовары» так схлопнулся с 60px до 25px. Поэтому
у `.sticky-aside` стоит `> * { flex-shrink: 0 }`.

## Подтверждения действий

`useToast()` — одна лента в правом нижнем углу, подключена в layout
компонентом `UiToasts`. Вызов: `toast.show('Товар в корзине')`,
второй аргумент — `'error'` для красного варианта. Сообщение само
исчезает через 3 секунды, по клику закрывается раньше.

## Тексты и локали

Ни одной русской строки в разметке — весь видимый текст лежит в
`apps/host/i18n/locales/ru.json` и `uz.json`. Файлы повторяют друг друга
ключ в ключ; `npm run i18n:todo` это проверяет и печатает, сколько строк
ещё ждут узбекского перевода.

Правила:

| Где | Как |
| --- | --- |
| В шаблоне | `{{ $t('common.addToCart') }}`, атрибуты — `:aria-label="$t('...')"` |
| В скрипте | `const { t } = useI18n()`, дальше `t('...')` |
| В массиве данных (вкладки, меню, колонки футера) | в поле лежит **ключ**, перевод берётся на месте вывода: `{{ $t(tab.label) }}` |
| Заголовок страницы | `useSeoMeta({ title: () => t('...') })` — функция, иначе при смене языка заголовок не обновится |
| Подстановка внутри фразы | `$t('ui.cart.item.sellerLabel', { title })`, в сообщении `Продавец: «{title}»` |

Ключи именуются `ui.<слой>.<файл>.<строка>`; то, что встречается больше
чем в одном месте, лежит в `common`, `catalog`, `cart`, `account` и других
смысловых секциях.

Множественное число собирается утилитой `plural()` — словоформы приходят
из локали: `plural(n, $t('common.tovar1'), $t('common.tovar2'), $t('common.tovar5'))`.
В узбекском форма одна, туда пишется одно и то же слово трижды.

Числа и деньги не переводятся: `formatMoney()` и `groupDigits()` считают
разряды сами и ставят неразрывный пробел, поэтому вырезать слово «сум»
из готовой строки не нужно — для цены без валюты есть `groupDigits(toSum(value))`.

Что намеренно **не** вынесено в локали: названия категорий, товаров и
продавцов, бейджи и статусы заказа — они приходят из API и локализуются
на бекенде по заголовку `accept-language` (так уже сделано для баннеров).
Моковые адреса и имена — тоже данные, а не интерфейс.

## Иконки

`UiIcon` подставляет SVG инлайном. Пропс `color` перекрашивает белую
выгрузку — часть иконок в макете лежит на цветной подложке и без этого
не видна на светлом фоне.

```vue
<UiIcon name="chevron-right" color="currentColor" :size="20" />
```

Все файлы в `layers/shared/app/assets/icons` — выгрузка из Figma.
Рисовать иконки вручную нельзя; исключение задокументировано в коде
(`minus.svg` — в макете состояние «минус» не нарисовано, собран из `add.svg`).

## Чего не делать

- задавать затемнение, ширину окна, крестик или высоту кнопки числом;
- заводить ещё один компонент кнопки или крестика;
- ставить отступ между секциями «на глаз» — только `--section-gap`
  или значение, сверенное с макетом и записанное комментарием.

## Состояния

Каждый интерактивный элемент обязан иметь четыре состояния. Значения
заданы один раз в `UiButton` / `UiCloseButton`, остальные элементы
повторяют ту же логику.

| Состояние | Как выглядит |
| --- | --- |
| `:hover` | фон на один шаг темнее (`primary` → `#24B238`, `secondary` → `#E7EBF1`), текстовые — подчёркивание |
| `:active` | ещё на шаг темнее (`primary` → `#1F9C31`) |
| `:disabled` | `opacity: .5`, `cursor: default`, клики не проходят |
| `:focus-visible` | кольцо `--focus-ring` (`0 0 0 3px rgb(41 200 64 / 35%)`), `outline: none` |

Наведение на карточку товара и строку каталога подсвечивает фон `#F7F9FC`,
наведение на иконку соцсети — `scale(1.08)`.

### Базовые состояния — общий блок в `main.css`

Там, где компонент не задал своего, срабатывает базовое правило: наведение
на любую кнопку, ссылку или элемент с `tabindex="0"` даёт `opacity: .82`.
Селектор целиком обёрнут в `:where(...)`, поэтому его вес — только `:hover`
(`0-1-0`), и собственное правило компонента всегда побеждает.

Непрозрачность, а не `filter`: `filter` делает элемент содержащим блоком для
`absolute`-потомков и сдвигает бейджи на карточках товара.

Поля ввода не наследуют шрифт сами — в базовом блоке стоит
`button, input, select, textarea { font: inherit; }`. Без этого браузер
подставляет им Arial: так поля диалога входа набирались Arial 37.6px вместо Inter.

### Заголовок страницы

На каждой странице ровно один `h1` и ровная иерархия уровней — без скачков
через уровень. Там, где заголовка нет в макете, он ставится скрытым:

```vue
<h1 class="visually-hidden">Корзина</h1>
```

Утилита `.visually-hidden` живёт в `main.css`: элемент не виден, но читается
скринридером и учитывается поисковиком.

### Отмена вместо подтверждения

Необратимое действие не блокируется диалогом «вы уверены?», а даёт отменить
себя из подтверждения — так быстрее и меньше кликов:

```ts
toast.show('Товар удалён из корзины', 'success', {
  label: 'Вернуть',
  run: () => cart.addItem(skuId, quantity),
})
```

Подтверждение с кнопкой отмены живёт 6 секунд вместо трёх.

### Как проверять состояния

Базовый `transition` длится 150 мс. Замер computed-стилей сразу после `hover`
или `Tab` попадает в середину анимации и покажет почти нулевые значения —
в аудите это дало ложную находку «нет кольца фокуса». Между действием и
чтением стиля нужна выдержка не меньше 260 мс.

## Формы входа

Три состояния из макета (`SIng`), и меняться они должны вместе:

| Экран | Панель | Содержимое |
| --- | --- | --- |
| Вход | 586×469 | телефон `+998` + пароль, кнопка `#43AD33` 536×68.8 r21.9, ссылка на регистрацию |
| Регистрация | 586×482 | только телефон, ссылка на вход, неактивная кнопка, согласие |
| Код из SMS | 586×462 | пять ячеек 94.9×100.7, номер с карандашом, отсчёт 01:30 |

Вход хранится в `useAuthStore` (`localStorage`, ключ `zoo:auth`).
Защищённое действие вызывает `auth.requireAuth()` — он сам открывает диалог,
если пользователь гость. Так сделано «Оформить» в корзине и «Купить в 1 клик».
